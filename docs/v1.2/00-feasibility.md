# v1.2 · 00 需求收集与可行性（安全底座 + 门控诊断）

> 状态：已归档（01/02 锁定）　日期：2026-11-25　分支：`feature/v1.2-security`
> 上游：[../08-a11y-detection-surface.md](../08-a11y-detection-surface.md)（检测面与 P0 建议）
> 目标：把"谁都能调"的本地控制接口收口，并让服务端能识别"树被门控"

## 1. 背景

- 驱动 `127.0.0.1:8899` **无鉴权**：任何有 `INTERNET` 权限的应用都能读屏、截图、点击；
- 浏览器可用 `text/plain` 发简单请求（无预检）盲发指令；
- 微信等应用在"无非白名单辅助服务"时只导出 1 个节点，服务端目前无法区分"页面空白"与"树被门控"；
- 兼容模式（`tools/a11y-compat.sh`）已存在，但需要人工判断何时开启。

## 3. 可行性

| RC | 结论 | 依据 |
| --- | --- | --- |
| RC-01 | ✅ | 应用私有目录 `files/vision.token`（0600），Termux 用 root 读取；已确认 `/data/data/dev.everything.vision` 可被 root 读取 |
| RC-02 | ✅ | 静态能力清单，无需额外权限 |
| RC-03 | ✅ | 解析前检查 header，成本 <1ms |
| RC-04 | ✅（启发式） | 阈值：`nodeCount ≤ 2` 且非系统包；需在微信/银行 App 验证误判 |
| RC-05 | ✅ | 服务端返回 hint，人工/上层决定是否 `a11y-compat.sh on` |
| RC-06 | ✅ | `GkdClient` 加工 header；401 时重读 token 重试一次 |
| RC-07 | ✅ | 脚本统一从 `su cat` 读 token |

## 4. 风险

| ID | 风险 | 应对 |
| --- | --- | --- |
| VR-01 | 清应用数据导致 token 变化 | 服务端 401 重读，部署脚本重新拉取 |
| VR-02 | 脚本遗漏 header → 全部 401 | 提供 `VISION_TOKEN` 环境变量与统一 helper |
| VR-03 | 门控阈值误判（白屏、加载页） | 结合包名与"页面是否有历史文本"，只作为提示 |
| VR-04 | 鉴权后调试不便 | `--token off`（仅开发）与 mock 驱动默认免鉴权 |
