## 7. 结论与建议

- `v1.0.0-rc` 达成「看 + 控 + 协议兼容 + 一键部署 + 回退」闭环，可在受控设备上试用；
- 性能（RSS、抓帧延迟）未达标，建议 v1.1 优先做「按需截图 + 节点缓存」；
- 兼容性与边界用例（分屏、受保护页、长按、非 root）需补测后才能称为 `v1.0.0`。

## 8. 真实任务验证：微信发送图片

**任务**：打开微信，给「空钟海报」发送一张图片。

**结果**：✅ 完成。测试图 `GKD-VISION TEST IMAGE`（900×900 渐变图）于 07:20 出现在「空钟海报」聊天中，无失败标记。

**执行路径**（全程截图 + 坐标点击，微信没有可用控件树）：

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 1 | `am start -n com.tencent.mm/.ui.LauncherUI` | 微信恢复到上次的「空钟海报」聊天 |
| 2 | 点击「相册」(160,1765) | 打开图片选择器 |
| 3 | 选中测试图（蓝渐变） | 绿色角标 1，发送按钮激活 |
| 4 | 点击「发送」(1121,2513) | 图片气泡出现，时间 07:20 |

**遇到的障碍**：

1. **微信控件树不可用**：`captureSnapshot` 只返回 1 个节点（`android.widget.FrameLayout`），微信屏蔽了无障碍节点暴露；
   → 只能靠截图识别与坐标点击，说明「纯控件树」方案覆盖不了微信这类应用。
2. **微信只有部分照片权限**：新写入 MediaStore 的测试图在选择器里不可见，`SEND` intent 也报「获取资源失败」；
   → 临时 `pm grant com.tencent.mm android.permission.READ_MEDIA_IMAGES` 后可见。
3. **悬浮窗干扰**：屏幕上有一个视频悬浮窗（PiP），点击坐标必须避开其区域。

**结论与建议**：

- 控件树驱动对微信无效，需要**视觉兜底**（模板匹配/OCR）作为 v1.1 的能力补齐（对应 G-20「P0 功能至少两条路」）；
- 图片发送这类跨应用任务，`READ_MEDIA_*` 权限与内容 URI 授权是主要摩擦点，建议在 v1.1 提供「授权引导」；
- 本次为真实发送，测试图已进入对方会话，不可撤回。
